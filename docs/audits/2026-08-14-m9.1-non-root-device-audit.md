# iSaver M9.1 非 Root 只读与设备概览验收审计

> 审计日期：2026-08-14
> 版本：0.5.1（versionCode 5）
> 设备：小米 9 Transparent Edition / Android 11 / API 30
> 结论：M9.1 本地范围通过；M10 远程继续冻结

## 1. 文档审计

- M1-M9 约定的本地范围已经完成，主规格 16.2 中 8 个遗留空复选框已按 M9 发布证据校正。
- 递归 chmod、owner/group 修改、APK 逆向、终端和远程文件属于明确排除或延期范围，不构成 M1-M9 未完成项。
- M10 仍位于独立 `:remote` 模块，`:app` 不依赖该模块，也不显示远程入口。

## 2. 实现结果

- `ModeAwareRootFileSystem` 覆盖完整文件系统接口，在同一 Repository 生命周期内动态切换 Root 与本地只读委派。
- `LocalReadOnlyFileSystem` 使用应用进程文件权限完成目录、stat、identity、metadata、range 和导出读取；所有写原语固定返回 `NOT_WRITABLE`。
- Root 不可用时自动进入非 Root 只读模式，不再阻断应用启动；模式由独立 DataStore 持久化。
- “视图”首页左上三横线与右侧更多按钮对齐；设备页提供 Root 模式开关和内部存储总量、已用、可用及使用率。
- 非 Root 长按面板隐藏移动、复制、重命名、删除、压缩和文本编辑入口；属性页只在条目确实可写时允许修改权限。
- instrumentation 使用专用 runner 显式激活测试进程 Root 委派，生产进程仍保持先只读、检查成功后 Root 的顺序。

## 3. 自动化证据

- 100 个 JVM 套件、664 个测试：0 failure / 0 error。
- `lintDebug`：通过。
- `:app:assembleDebug`、`:app:assembleDebugAndroidTest`：通过。
- `LocalReadOnlyFileSystemInstrumentedTest`：1/1 通过，验证 Android 应用可读目录、普通文件导出和写入拒绝。
- `RootStreamTransferInstrumentedTest`：7/7 通过，验证代理接入后 Root 保存链路无回归。
- 新增 Compose UI 类已编译；小米 9 的 Compose 宿主在 180 秒内无 JUnit 输出并超时，属于已知 MIUI runner 限制，不计为通过。

## 4. 小米 9 手工与 UIAutomator 证据

- Debug 0.5.1 通过 Root `pm install -r` 安装，MainActivity 正常 resumed。
- 视图首页同时存在“设备与设置”、居中“视图”和“更多操作”，左右动作 bounds 均为 132 x 132 px 且中心纵坐标一致。
- 设备页显示 Root 开启、`完整文件管理权限`，以及 242 GB 总量、46.3 GB 已用、196 GB 可用、19.1% 使用率；数值与设备文件系统同量级。
- 关闭 Root 后开关保持关闭并显示 `非 Root 只读，仅显示当前有权读取的内容`；强制停止并重启后仍保持只读偏好。
- 非 Root 可列出 `/storage/emulated/0` 当前应用进程可见目录；Android 11 scoped storage 隐藏无授权的随机文本文件，符合权限边界。
- 非 Root 长按目录仅显示分享、属性、添加到虚拟视图位置和多选，不显示移动、复制、重命名、删除或压缩。
- 不重启应用重新开启 Root 后恢复 `完整文件管理权限`，Root 流专项随后 7/7 通过。
- 最终日志未发现 iSaver `FATAL EXCEPTION` 或 ANR。

## 5. 剩余风险

- 非 Root 外部存储可见范围由 Android 版本、targetSdk、OEM scoped storage 策略和已有系统授权决定；本轮不引入 SAF 或 all-files 特权申请。
- 非 Root 真机本轮只覆盖 Android 11 小米 9；API 29/33/35 需在后续兼容矩阵复跑时补充真实文件可见性证据。
- MIUI Compose 测试宿主仍可能挂起，发布门禁继续使用硬超时，并以 JVM、编译和真实设备 UIAutomator 证据补足本轮 UI 验收。
