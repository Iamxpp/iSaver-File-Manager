# iSaver M7.1 虚拟视图位置统一改造需求与技术落地

> 文档版本：1.1
> 编制日期：2026-08-13
> 实施区间：M7 完成后、M8 开始前
> 文档性质：PRD + 交互规格 + SDD 增量设计 + 验收基线
> 关联基线：`iSaver_PRD_需求说明书.md`、`iSaver_SDD_系统设计文档.md`、`iSaver_现代Root文件管理器完整产品与技术规格.md`
> 实施状态：功能与 Slice F 验证已完成；本文档随最终提交推送后正式封板，M8 尚未实施

## 1. 变更目的

当前 iSaver 同时存在两套含义接近但入口割裂的位置管理能力：

1. “视图”页中的“自定义位置”保存真实目录路径。
2. 文件浏览页中的“收藏当前路径”“书签”和文件长按“收藏”保存文件或目录引用。
3. 回收站位于文件浏览页右上角菜单，与“通用位置”中的其他系统级入口分离。
4. 分享另存、移动目标和复制目标会复用“视图”页，但没有区分应用层逻辑位置和真实文件系统目录。

本改造将“自定义位置”“书签”“收藏”统一为“虚拟视图位置”，形成一棵完全由 iSaver 在应用层维护的逻辑树。虚拟树只用于组织和查找真实文件或真实目录的引用，不创建磁盘目录，不承载文件内容，也不改变真实路径。

本改造必须在 M8 双窗口与高级本地能力实施前完成，作为 M7 的信息架构收口里程碑，编号为 **M7.1**。

## 2. 范围与非目标

### 2.1 本轮范围

- 将主界面“自定义位置”改名为“虚拟视图位置”。
- 将旧自定义位置、书签和收藏统一到同一应用层虚拟树。
- 支持创建不限产品层级的虚拟视图文件夹。
- 支持将真实文件或真实目录作为叶子引用添加到指定虚拟文件夹。
- 支持备注、重命名、移动引用、移动虚拟文件夹、删除引用和删除虚拟文件夹。
- 将回收站移动到“通用位置”末尾。
- 从文件浏览页右上角菜单移除旧“回收站”“收藏/取消收藏当前路径”“书签”三个选项。
- 用“添加到虚拟视图位置”替代旧收藏动作，并要求选择目标虚拟文件夹。
- 在分享另存、移动目标、复制目标和解压目标流程中识别虚拟层，正确禁用保存或目标确认。
- 提供旧数据的 Room 无损迁移和回滚前备份策略。

### 2.2 明确不在本轮

- M8 的普通手机竖屏双窗口、横屏/平板双窗口。
- M8 的单窗图标/详细列表切换和双窗详细列表锁定。
- 文本编辑、Hex、文件对比和权限修改。
- 远程服务器和远程文件映射。
- 云同步、跨设备同步、共享虚拟视图配置。
- 在真实文件系统中创建与虚拟文件夹同名的目录。
- 把文件内容复制、移动或保存到虚拟文件夹。

## 3. 术语与核心模型

### 3.1 虚拟视图位置

“虚拟视图位置”是“视图”页中的应用层逻辑区域。它由虚拟文件夹和真实项目引用组成，所有层级、备注、排序和展开关系只存储在 iSaver 数据库中。

### 3.2 虚拟文件夹

- 节点类型为 `VIRTUAL_FOLDER`。
- 只用于分组，可以包含其他虚拟文件夹和真实项目引用。
- 不对应任何 Root 路径，没有 device/inode，不参与文件系统读写。
- UI 使用**边缘为虚线的文件夹图标**，必须与普通文件夹明显区分。
- 产品层面不限制嵌套层数；实现必须使用迭代遍历、父链循环检测和数据库约束，不能依赖递归调用栈无限增长。
- 虚拟视图根节点是应用内部隐式根，不直接作为用户可选的添加目标。

### 3.3 真实项目引用

- 节点类型为 `REAL_REFERENCE`。
- 目标可以是一个真实文件或真实目录。
- 必须是虚拟文件夹的直接子节点，不能成为任何节点的父节点。
- 在虚拟树中永远是叶子；真实目录不能在虚拟树内继续展开其磁盘子目录。
- 点击真实目录引用后，退出虚拟树展示并进入该真实路径的普通文件浏览页。
- 点击真实文件引用后，执行普通文件默认打开流程。
- 目录引用使用正常实线文件夹图标；文件引用使用对应文件图标。
- “一层”指真实项目在虚拟树中只占一个叶子节点，并不限制它在真实文件系统中的实际深度。

### 3.4 添加引用与保存文件

必须严格区分：

- **添加到虚拟视图位置**：只创建指向现有真实项目的数据库引用，不复制文件，不修改真实项目。
- **保存到真实目录**：把分享来源的字节写入已经校验的真实可写目录。

虚拟文件夹只能接收“引用”，不能接收“文件内容”。

## 4. 信息架构与主界面调整

### 4.1 “视图”页分区顺序

“视图”页保持以下顺序：

1. 应用位置。
2. 通用位置。
3. 虚拟视图位置。

现有“自定义位置”标题统一改为“虚拟视图位置”。代码、测试、可访问性描述和用户可见文案不得继续混用“自定义位置”“书签”“收藏夹”。历史数据库表名可以在迁移期保留，但不能泄漏到 UI。

### 4.2 通用位置

“回收站”移动到“通用位置”的最后一个，显示在内部存储、下载、图片、文档、视频等真实位置之后。

回收站是 iSaver 的系统逻辑入口，不属于虚拟树：

- 不允许移动、重命名或删除这个入口。
- 不允许将回收站添加到虚拟视图位置。
- 保存模式下点击回收站不进入可保存目标。
- 图标应与普通目录区分，沿用回收站语义图标。

### 4.3 虚拟视图位置空态

首次使用且没有任何虚拟文件夹时显示：

- 标题：“虚拟视图位置”。
- 空态操作：“新建虚拟视图文件夹”。
- 不自动显示可被误认为真实目录的空文件夹。

旧数据迁移时会自动创建“未分组”虚拟文件夹，因此有旧自定义位置或旧书签的用户不会进入空态。

### 4.4 右上角菜单调整

普通真实目录浏览页右上角菜单删除以下三个旧选项：

1. 回收站。
2. 收藏当前路径/取消收藏当前路径。
3. 书签。

新增一个统一动作：

- “添加当前路径到虚拟视图位置”。

该动作打开虚拟文件夹选择器，不直接创建引用。当前路径已存在于某个虚拟文件夹时仍可添加到其他虚拟文件夹；已经包含该路径的目标虚拟文件夹必须禁用并显示“此位置已添加”。

“视图”页右上角菜单至少提供：

- 新建虚拟视图文件夹。
- 管理虚拟视图位置。

文件浏览页仍保留新建、任务中心、深度搜索、显示模式和排序等与本改造无冲突的菜单项。

## 5. 用户交互需求

### 5.1 从真实文件系统添加项目

#### 文件或目录长按

长按操作小窗中的旧“收藏/取消收藏”统一替换为：

- “添加到虚拟视图位置”。

流程：

1. 用户长按真实文件或真实目录。
2. 点击“添加到虚拟视图位置”。
3. 打开虚拟文件夹选择器，只展示虚拟文件夹，不展示真实项目引用作为可进入或可选目标。
4. 用户选择一个虚拟文件夹。
5. 可选填写备注名称；默认使用真实项目名称。
6. 确认前重新读取目标项目类型和 identity。
7. 创建引用并显示“已添加到‘目标虚拟文件夹名’”。

选择器不允许把引用添加到正常实线图标的真实目录引用下。若用户点击真实引用，显示：

> 真实文件和文件夹只能作为虚拟视图的最后一层，不能在其下添加内容。

#### 当前目录

当前目录通过右上角“添加当前路径到虚拟视图位置”进入同一选择器和确认流程，不再存在独立的当前路径收藏状态。

### 5.2 目标重复规则

- 同一真实路径可以出现在不同虚拟文件夹中，便于按不同用途组织。
- 同一虚拟文件夹内不得重复添加同一 canonical path 和 entry type。
- 重复判断不能只比较备注名。
- 同一路径被外部替换后仍使用已保存 identity 判断原引用是否失效，不能把新项目静默认作旧引用。
- iSaver 自身移动或重命名真实项目后，所有匹配旧 identity 的引用应在同一事务中更新目标路径，并保留各自备注和虚拟父节点。

### 5.3 虚拟文件夹管理

用户可以在虚拟根或任意虚拟文件夹中：

- 新建子虚拟文件夹。
- 修改虚拟文件夹名称和备注。
- 调整同级排序。
- 将虚拟文件夹移动到另一个虚拟文件夹。
- 删除空虚拟文件夹。
- 删除非空虚拟文件夹。

删除非空虚拟文件夹必须二次确认，确认文案明确：

> 只会移除这个虚拟分组及其中的引用，不会删除设备上的任何文件或文件夹。

移动虚拟文件夹时必须拒绝：

- 移动到自身。
- 移动到自身任意后代。
- 形成任何父链循环。

产品不限制层数，但路径面包屑必须支持横向滚动或折叠，不能因层级过深挤压页面。

### 5.4 真实引用管理

长按虚拟树中的真实项目引用，显示应用层动作：

- 打开。
- 编辑备注。
- 移动到其他虚拟文件夹。
- 再添加到其他虚拟文件夹。
- 从虚拟视图移除。
- 查看真实路径和可用状态。

此处不得直接展示“删除真实文件”。用户若要执行真实文件操作，必须先打开所在真实位置，再使用普通文件管理操作。

“从虚拟视图移除”只删除当前引用，不影响同一路径在其他虚拟文件夹中的引用，也不影响设备文件。

### 5.5 备注规则

- 虚拟文件夹和真实项目引用都支持备注显示名称。
- 备注只影响虚拟视图展示，不重命名真实项目。
- 备注不能为空，去除首尾空白后长度建议限制为 1 至 120 个 Unicode code point。
- 同一虚拟文件夹内允许备注重名，但必须通过副标题显示真实文件名或路径以避免误认。
- 真实引用至少显示备注、类型和可用状态；详细模式显示真实路径。

### 5.6 不可用引用

真实项目被外部移动、删除、替换或权限变更后：

- 引用保留，不自动删除。
- 使用弱化样式和“不可用”状态。
- 点击时先复核 canonical path、类型和 identity。
- 提供“重新定位”“重试校验”“编辑备注”“移除引用”。
- 重新定位必须由用户选择新的真实项目，并重新绑定 identity。

## 6. 保存模式与目标选择器规则

### 6.1 分享另存

用户通过微信或其他应用进入“保存到 iSaver”时，“视图”页仍展示虚拟视图位置，但：

- 位于虚拟根或任意虚拟文件夹时，“存储”按钮必须禁用并变灰。
- 页面显示非阻断提示：“虚拟视图文件夹只用于分组，不能保存文件。请选择一个真实文件夹。”
- 点击真实文件引用不能作为保存目标，应提示“文件不能作为保存位置”。
- 点击真实目录引用后，进入该目录的普通真实文件浏览页。
- 只有真实目录完成 Root 存在性、目录类型、可写性、符号链接和 canonical identity 复核后，“存储”按钮才可启用。
- 从真实目录返回虚拟树时必须立即清空旧保存目标并再次禁用按钮，防止保存到不可见目录。

### 6.2 移动、复制与解压目标

移动、复制和解压目标选择器遵循相同逻辑：

- 虚拟文件夹不是文件系统目标，“移动到这里”“复制到这里”“解压到此处”均禁用。
- 点击真实目录引用进入真实目录后，按既有目标校验规则启用操作。
- 真实文件引用不可进入，不可作为目标。
- 禁用原因必须通过页面提示和无障碍语义同时提供。

### 6.3 添加引用选择器

“添加到虚拟视图位置”的选择器与文件操作目标选择器必须是不同模式：

- 只允许选择 `VIRTUAL_FOLDER`。
- 不允许选择隐式虚拟根。
- 不展示“保存”“移动到这里”等物理操作文案。
- 确认按钮文案为“添加到这里”。
- 没有虚拟文件夹时提供“新建虚拟视图文件夹”，创建成功后停留并自动选中。

## 7. 视觉与可访问性规格

### 7.1 图标

- 虚拟文件夹：文件夹轮廓边缘为虚线，内部不使用云、网络或磁盘符号。
- 真实目录引用：正常实线文件夹图标。
- 真实文件引用：按 MIME/扩展类型使用现有文件图标。
- 回收站：专用回收站图标。
- 不可用引用：图标和文字降低强调度，但仍满足可读性对比度。

虚线文件夹图标应作为项目资源或现有图标体系的受控扩展，不应通过在 UI 上叠加多个字符模拟。

### 7.2 列表内容

虚拟文件夹：

- 主标题：用户名称。
- 副标题：`虚拟文件夹 · N 项`。

真实目录引用：

- 主标题：备注，没有备注时使用真实目录名。
- 副标题：`文件夹 · /真实/路径`，路径可省略中间段。

真实文件引用：

- 主标题：备注，没有备注时使用真实文件名。
- 副标题：类型、大小和真实父路径。

### 7.3 无障碍

- 虚拟文件夹语义必须读作“虚拟文件夹：名称”，不能只读作“文件夹”。
- 真实目录引用读作“真实文件夹引用：名称”。
- 禁用保存按钮必须提供禁用原因。
- 虚线不能是区分虚拟与真实的唯一手段，文字副标题必须同时标明节点类型。

## 8. 数据模型

### 8.1 新表 `virtual_view_nodes`

建议新增统一表，而不是继续扩展 `custom_locations` 和 `bookmarks` 两套表：

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT PK | 随机 UUID，不包含路径信息 |
| `parentId` | TEXT NULL | 父虚拟文件夹；顶层虚拟文件夹为 NULL |
| `nodeType` | TEXT | `VIRTUAL_FOLDER` 或 `REAL_REFERENCE` |
| `displayName` | TEXT | 用户备注或虚拟文件夹名 |
| `targetPath` | TEXT NULL | 真实引用的规范化绝对路径 |
| `entryType` | TEXT NULL | `FILE` 或 `DIRECTORY` |
| `device` | INTEGER NULL | 引用创建时 identity |
| `inode` | INTEGER NULL | 引用创建时 identity |
| `available` | INTEGER | 当前可用状态 |
| `sortOrder` | INTEGER | 同级顺序 |
| `createdAt` | INTEGER | 创建时间 |
| `updatedAt` | INTEGER | 更新时间 |

约束：

- `VIRTUAL_FOLDER` 的 `targetPath/entryType/device/inode` 必须为空。
- `REAL_REFERENCE` 的 `targetPath` 和 `entryType` 必须非空。
- `REAL_REFERENCE.parentId` 必须指向 `VIRTUAL_FOLDER`，不得为空。
- `parentId` 不得指向当前节点。
- 同一父节点下 `sortOrder` 应稳定且可重排。
- 同一虚拟文件夹内对 `(targetPath, entryType)` 建立唯一约束；不同虚拟文件夹允许重复引用。
- 删除虚拟文件夹必须由仓库显式事务处理，不依赖无提示级联。

SQLite 无法独立表达所有跨行类型约束，Repository 必须在事务内校验父节点类型和父链，测试中直接构造非法行验证拒绝策略。

### 8.2 领域模型

建议使用：

```text
VirtualViewNode
├── VirtualFolder(id, parentId, displayName, sortOrder, timestamps)
└── RealReference(
      id, parentId, displayName,
      targetPath, entryType, identity,
      available, sortOrder, timestamps
    )
```

不要让 `VirtualFolder` 实现 `RootPath`，也不要把它伪装成 `StorageLocation.Direct`。类型层面区分应用逻辑节点与真实文件系统目标，才能避免保存门禁遗漏。

### 8.3 导航状态

新增显式页面状态：

```text
ViewDestination
├── Overview
├── VirtualFolder(folderId, breadcrumbIds)
└── RealBrowser(rootPath, sourceVirtualNodeId?)
```

保存和文件操作目标能力由 destination 类型计算：

- `Overview`：不可写。
- `VirtualFolder`：不可写，只可添加引用或管理逻辑节点。
- `RealBrowser`：重新校验后按真实目录能力决定。

不得用“当前路径字符串是否为空”猜测页面类型。

## 9. 旧数据迁移

### 9.1 迁移原则

- 数据库升级必须原子完成。
- 迁移前由 Room 正常备份/事务保护，不删除真实文件。
- 原 `custom_locations` 和 `bookmarks` 数据全部进入新树后，旧表先保留一个数据库版本作为只读迁移来源；确认发布稳定后再单独版本删除。
- 迁移可重复检测，不能因应用异常重启生成重复节点。

### 9.2 迁移映射

数据库升级时创建一个顶层虚拟文件夹：

- 名称：“未分组”。
- 固定迁移 ID，确保幂等。

旧 `custom_locations`：

- 每条转为 `REAL_REFERENCE(DIRECTORY)`。
- `displayName` 保留。
- `absolutePath` 转为 `targetPath`。
- 放入“未分组”。
- 首次加载后重新探测 identity 和可用状态。

旧 `bookmarks`：

- 文件与目录均转为 `REAL_REFERENCE`。
- 保留显示名称、entryType、device/inode 和 available。
- 有 `groupName` 时，为每个唯一旧分组在“未分组”旁创建一个顶层虚拟文件夹，并放入对应引用。
- 无 `groupName` 时放入“未分组”。
- 旧颜色字段不作为首版虚拟树核心能力；可保留在迁移兼容字段或后续元数据表中，不得因本轮迁移丢失。

若旧自定义位置与旧书签在同一迁移目标文件夹中指向同一路径：

- 合并为一个引用。
- 优先保留书签的 identity 和可用状态。
- 显示名称优先保留用户修改时间较新的值；无法判断时优先旧书签显示名称。

### 9.3 迁移后的 UI

### 10.2 Repository API 基线

```text
observeChildren(parentFolderId)
observeBreadcrumb(folderId)
createFolder(parentFolderId?, name)
renameNode(nodeId, displayName)
moveNode(nodeId, targetFolderId)
deleteFolder(nodeId, confirmed)
addReference(targetFolderId, path, type, identity, displayName)
removeReference(referenceId)
relocateReferences(oldIdentity, newPath, newIdentity)
setReferenceAvailability(referenceId, available)
rebindReference(referenceId, newPath, newIdentity)
```

所有多步变更必须在 Room 事务中完成。父链校验应设置访问节点集合，检测重复 ID 后立即返回 `VIRTUAL_CYCLE`，不能无限遍历。

### 10.3 Root 边界

- 创建、重命名、移动或删除虚拟文件夹不请求 Root。
- 添加真实引用时才通过现有 typed Root API 获取 canonical path、类型和 identity。
- 打开引用、作为真实目标或执行真实操作前必须重新校验。
- 虚拟节点 ID、备注和父子关系不得传入 Shell 命令。

## 11. 错误与提示文案

| 场景 | 文案 |
|---|---|
| 虚拟文件夹中尝试保存 | 虚拟视图文件夹只用于分组，不能保存文件。请选择一个真实文件夹。 |

## 16. 已确认的产品决策

1. “书签”和“收藏”不再作为独立产品入口，统一为虚拟视图中的真实项目引用。
2. 虚拟文件夹只分组，不映射磁盘路径，不保存字节。
3. 文件和目录都可以被添加，但都只能作为虚拟树最后一层。
4. 真实目录引用点击后进入真实文件浏览器，后续磁盘层级属于普通浏览，不属于虚拟树。
5. 同一真实项目可以被添加到多个虚拟文件夹；同一虚拟文件夹内不能重复。
6. 虚拟文件夹产品层面不限层数，工程实现必须防循环和栈溢出。
7. 分享保存等目标流程可经过虚拟树导航，但只能在真实可写目录执行写入。
8. 删除虚拟内容永不删除真实文件；真实删除只能在普通文件浏览器中执行。
9. 回收站归入通用位置，不归入虚拟树。
10. 本改造作为 M7.1 完成，完成后再开始 M8。
