# iSaver M9.1 非 Root 只读与设备概览需求与技术落地

> 版本：1.0
> 日期：2026-08-14
> 状态：已完成
> 依赖基线：M1-M9 本地能力已完成
> 范围约束：M10 远程文件继续冻结

## 1. 背景与目标

iSaver 现有版本在启动时强制检查 Root，Root 不可用时阻断全部本地浏览。M9.1 将访问能力拆成两种由用户控制的模式：

- **Root 模式**：复用现有 typed Root 文件系统和完整本地文件管理能力。
- **非 Root 只读模式**：只使用 iSaver 应用进程自身权限读取目录和普通文件，不申请提权，不执行任何文件系统写操作。

本轮同时在“视图”首页增加左上菜单入口，并提供设备页面显示 Root 模式开关和手机内部存储使用情况。

## 2. 范围

### 2.1 本轮必须完成

1. “视图”根页面左上角显示三横线菜单按钮，与右上角更多按钮等宽、等高并水平对齐。
2. 点击菜单按钮进入独立“设备”页面；系统返回和页面返回按钮均回到原页面。
3. 设备页面显示“Root 模式”开关及当前模式说明。
4. 设备页面显示内部存储总容量、已用容量、可用容量和使用比例。
5. Root 模式默认开启，以保持既有用户行为；用户关闭后持久化为非 Root 只读模式。
6. 非 Root 模式只能读取应用进程实际有权限访问的目录和普通文件；无权限目录返回明确错误，不伪装为空目录。
7. 非 Root 模式下所有新建、保存、编辑、改权限、复制、移动、重命名、删除、压缩和解压发布操作必须在数据层统一拒绝。
8. 非 Root 模式仍允许目录浏览、即时过滤、深度搜索、属性查看、只读预览、Hex、校验和、比较、默认打开和对外分享，但仅限应用进程可读的普通文件。
9. 开启 Root 模式时先重新检查 Root；授权成功后再切换。授权失败时继续停留在非 Root 模式并显示原因。
10. 模式切换后刷新位置、虚拟引用、最近项目和当前浏览目录，不能继续使用切换前缓存的权限结论。

### 2.2 明确不做

- 不启动 M10，不显示远程服务器入口，不向 `:app` 引入远程依赖。
- 不在本轮引入 SAF 目录授权树、Shizuku、ADB 常驻服务或系统分区重新挂载。
- 不承诺非 Root 模式读取 Android 沙箱、其他应用私有目录或系统保护目录。
- 不允许非 Root 模式借助 Android 普通写权限执行写操作；“非 Root”在本轮固定为只读。
- 不实现存储清理、分类扫描、重复文件清理或磁盘占用分析。

## 3. 交互规格

### 3.1 视图首页入口

- 三横线按钮只在“视图”根页面显示。
- 进入虚拟视图文件夹后左侧仍显示返回按钮，不能同时显示三横线按钮。
- 按钮无文字标签，辅助功能描述为“设备与设置”，测试标签为 `views-device-menu`。

### 3.2 设备页面

- 顶部标题为“设备”，左侧返回按钮；不显示搜索框、底部主导航和更多菜单。
- 第一段为“访问模式”。“Root 模式”使用系统开关，副文案按状态显示：
  - 开启成功：`完整文件管理权限`
  - 关闭：`非 Root 只读，仅显示当前有权读取的内容`
  - 检查中：`正在检查 Root 权限`
  - 检查失败：显示脱敏后的用户可读原因，开关保持关闭
- 第二段为“内部存储”。显示使用比例进度条、已用/总容量和可用容量。
- 存储统计读取失败时显示“无法读取存储信息”，不能崩溃或显示负数。

### 3.3 模式切换

- Root -> 非 Root：立即切换数据层代理，取消危险目标选择状态，刷新当前页面，然后持久化偏好。
- 非 Root -> Root：保持非 Root 代理，进入检查状态；只有 `uid=0` 检查成功才切换并持久化。
- Root 检查失败：保持非 Root，展示原因，允许用户再次开启重试。
- 冷启动读取持久化偏好。偏好不存在时按 Root 模式启动；Root 不可用时自动进入非 Root 只读模式，不再阻断启动。

## 4. 数据与架构

### 4.1 核心模型

```kotlin
enum class FileAccessMode { ROOT, LOCAL_READ_ONLY }

data class DeviceStorageUsage(
    val totalBytes: Long,
    val availableBytes: Long,
) {
    val usedBytes: Long
    val usedFraction: Float
}
```

### 4.2 组件职责

| 组件 | 职责 |
| --- | --- |
| `FileAccessModeStore` | DataStore 持久化首选模式，不保存 Root 技术输出 |
| `FileAccessController` | 维护当前已生效模式；切换先后顺序由 Root 门禁协调 |
| `ModeAwareRootFileSystem` | 所有 `RootFileSystem` 方法按当前模式动态委派，防止旧 Repository 绕过模式切换 |
| `LocalReadOnlyFileSystem` | 通过 Android/Java 文件 API 实现受权限约束的读取原语；所有写原语统一拒绝 |
| `DeviceOverviewRepository` | 使用 `StatFs` 读取内部共享存储容量，完成边界校验 |
| `DeviceSettingsViewModel` | 组合访问模式、Root 检查状态和存储概览 |

### 4.3 非 Root 读取规则

- 路径仍使用已验证的绝对 `RootPath` 值对象，保持上层契约兼容。
- `readDirectory` 必须区分不存在、不是目录和没有读取权限；`listFiles() == null` 视为不可读，不视为空目录。
- 每个目录项由 `lstat` 读取类型和身份；符号链接保持标记，不跟随进入普通文件操作。
- 上报的 `writable` 与父目录 `parentWritable` 固定为 `false`，即使 Linux DAC 表面允许写入。
- `copyToOutput`、`readRange` 和 metadata 只接受应用进程可读的普通文件，并在读取前后核对版本。
- 非 Root 文件读取不经过 `su`、libsu shell 或 native Root helper。

### 4.4 只写保护

`ModeAwareRootFileSystem` 必须覆盖完整 `RootFileSystem` 接口。处于 `LOCAL_READ_ONLY` 时，任何写原语均委派到 `LocalReadOnlyFileSystem` 并返回：

- `ErrorCode.NOT_WRITABLE`
- 用户信息：`非 Root 模式仅支持只读浏览`

UI 的禁用状态用于减少误操作，但不能替代数据层门禁。

## 5. 安全与失败策略

- Root 开关关闭后，不得保留任何“仍由 Root 完成读取”的静默回退。
- Root 开关开启失败时，不得把首选模式写成 Root。
- 模式切换不得自动重放任务中心中的写任务；未完成写任务继续遵守 `NEVER_REPLAY/NEEDS_REVIEW`。
- 切换到非 Root 前取消分享另存、移动、复制和解压目标选择，避免旧的可写目录结论继续启用确认按钮。
- 本地读取异常只能返回脱敏技术信息，不能把其他应用私有路径内容写入日志。
- 存储容量计算使用饱和边界检查，防止块数乘法溢出。

## 6. 测试与验收

### 6.1 JVM 测试

- 首次启动默认 Root；模式偏好可持久化并恢复。
- Root 检查失败自动进入本地只读模式；再次授权成功可切回 Root。
- 模式代理在同一 Repository 实例存活期间动态切换委派对象。
- 本地文件系统可列出可读目录、读取普通文件范围和导出内容。
- 本地文件系统对全部写原语返回 `NOT_WRITABLE`。
- 无权限目录不返回成功空列表；符号链接不作为普通目录跟随。
- 容量模型对零容量、边界值和正常比例计算正确。

### 6.2 Compose/UI 测试

- 视图根页面显示三横线按钮，虚拟子目录显示返回按钮且不显示三横线。
- 点击入口显示“设备”、Root 开关和内部存储信息。
- Root 检查中开关不可重复触发；失败后开关保持关闭并显示原因。
- 返回按钮恢复视图首页和底部导航。

### 6.3 小米 9 实机

1. Root 模式启动，浏览 `/data/local/tmp/isaver-test`，确认既有 Root 浏览与写入专项无回归。
2. 在设备页关闭 Root 模式，确认页面显示只读状态。
3. 浏览应用进程可读目录并打开一个专用测试文件；进入不可读目录时显示权限错误。
4. 尝试触发新建/移动/删除/保存，确认 UI 禁用或数据层返回只读错误，文件内容无变化。
5. 在不重启应用的情况下重新开启 Root，确认授权成功后恢复 Root 目录浏览。
6. 核对内部存储总量、可用量与 `df` 同量级，比例在 0% 到 100%。
7. 检查无 `FATAL EXCEPTION`、ANR 和敏感路径日志。
