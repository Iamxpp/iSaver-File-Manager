## 1. 产品概述

### 1.1 产品名称

iSaver（现代 Files 风格 Android Root 文件管理器）

### 1.2 产品定位

iSaver 融合 iOS Files 的清晰视觉与 MT 管理器的高效率文件操作，将 Android 中分散的软件存储目录整理成统一、清晰的文件管理器视图。用户不需要记忆微信等应用的真实路径，也可以直接浏览完整 Root 文件系统并完成打开、分享、复制、移动、压缩和恢复等操作。

首版主要面向已经 Root 的 Android 用户。应用启动后必须检查 Root 权限；未获得 Root 权限时，不进入文件管理主页，而是明确提示“请授予 Root 权限后运行 iSaver”。首版不实现 SAF、Shizuku 或普通权限降级模式。

iSaver 同时保留原有“文件另存助手”能力：第三方应用可通过系统分享把文件发送给 iSaver，用户在同一套 iOS Files 风格视图中选择目标目录并保存。

完整文件管理器能力的产品与技术细节见 [iSaver_现代Root文件管理器完整产品与技术规格.md](iSaver_现代Root文件管理器完整产品与技术规格.md)。

### 1.3 核心价值

- 用软件名称和用途代替难以理解的 Android 绝对路径。
- 将一个软件的多个存储位置聚合到同一入口。
- 允许用户把真实文件或目录添加为“虚拟视图位置”的叶子引用，并用不限层级的虚拟文件夹分组。
- 提供接近 iOS Files 的简洁视觉、分组与逐层浏览体验。
- 保留从微信、浏览器、邮件等应用接收并另存文件的闭环。
- 用统一长按操作面板完成打开方式、分享、复制、移动、重命名、压缩、删除和属性查看。
- 在手机单窗与普通手机竖屏、横屏、折叠屏和平板双窗之间提供一致的文件操作模型。

### 1.4 典型使用场景

场景一：浏览应用文件

```text
启动 iSaver
  -> 授予 Root 权限
  -> 在“应用位置”中选择微信
  -> 选择“接收文件”“图片”或其他实际存在的位置
  -> 浏览目录和文件
```

场景二：整理虚拟视图位置

```text
在视图页新建虚拟文件夹
  -> 从当前目录菜单或文件长按面板选择“添加到虚拟视图位置”
  -> 选择一个虚拟文件夹并填写备注
  -> iSaver 使用 Root 校验真实项目并保存叶子引用
  -> 从虚拟视图位置快速打开文件或进入真实目录
```

场景三：接收并另存文件

```text
微信/浏览器/其他 App
  -> 分享或用其他应用打开
  -> 选择 iSaver
  -> 在位置视图中选择目标目录
  -> 保存文件
```

## 2. 产品目标与边界

### 2.1 0.1.x 基线目标

- Root 权限检查与可理解的失败提示。
- iOS Files 风格“位置”首页。
- 按软件聚合常用存储路径，首批内置微信路径模板。
- Root 目录浏览、文件列表与基础信息展示。
- Root 自定义绝对路径的添加、编辑、删除与重新校验。
- 新建文件夹。
- 接收单个分享文件并保存到 Root 可写目录。
- 文件重名、空间不足、Root 中断等失败处理。
- “最近项目 / 视图 / 浏览”三标签导航与 iOS Files 高保真视觉。
- 列表/图标显示，以及按名称、种类、日期、大小排序。
- ZIP 创建；ZIP、TAR、TAR.GZ、7Z、RAR 浏览与解压。
- 本地文件管理器完成前不暴露远程服务器入口，也不安排远程新增功能。

### 2.2 0.1.x 非目标与后续范围

- 不支持非 Root 设备的完整功能，不设计普通模式、SAF 模式或 Shizuku 模式。
- 0.1.x 暂不实现删除、移动、批量复制、重命名、多文件对外分享或全盘内容搜索；单文件 Root 文件对外分享首个切片已在 M6 落地，其余能力进入 0.2.0+ 完整文件管理器路线。
- 不自动扫描并识别所有已安装应用的全部目录。
- 不实现云盘、WebDAV、SMB、自动同步、后台定时同步或双向目录镜像。
- 不提供 SFTP、FTPS、FTP 连接、浏览或传输；远程功能延后到本地文件管理器完整验收之后。
- 不修改应用数据库、账号信息或系统关键配置。
- 不复制 MT 的品牌、界面或逆向修改工具；iSaver 只参考其高效文件管理工作流，并以现代视觉和更严格安全策略重新实现。

### 2.3 0.2.0+ 完整文件管理器目标

- 点击文件通过 Android 默认应用打开；无默认应用时显示系统选择器。
- 长按文件或多选项目后，可分享、复制、移动、重命名、压缩、删除和查看属性。
- 移动/复制/解压共用目标选择器，支持新建文件夹、冲突预览、无覆盖和任务进度。
- 共享存储删除默认进入可恢复回收站；系统关键目录默认只读。
- 支持搜索、过滤、虚拟视图位置、历史、批量重命名、校验和和统一任务中心。
- 普通手机竖屏、横屏、折叠屏和平板提供双窗口快捷复制/移动；双窗口锁定详细列表显示，单窗可切换图标/详细列表。
- 详细 FR、状态、错误流程和技术实现以完整规格文档为准。

### 2.4 本地优先发布门禁

- 0.2.0 至 0.5.x 只排期本地文件管理能力；远程适配器仅接受阻断构建或安全回归的必要维护。
- 远程 UI、连接配置、远程目录和远程传输不得通过运行时开关、调试入口或未公开导航提前暴露。
- 启动远程里程碑前，本地默认打开、对外分享、复制、移动、重命名、解压、新建、删除/回收站、多选、搜索、任务中心和双窗必须全部完成验收。
- 本地发布门禁必须通过单元测试、Lint、Debug 构建、小米 9 Root 真机流程和至少一轮 Android 兼容矩阵回归。

## 3. 用户与运行环境

### 3.1 目标用户

- 已 Root、需要快速访问应用文件目录的 Android 用户。
- 不希望记忆 `/data/user/0/...`、`/storage/emulated/0/Android/...` 等路径的用户。
- 经常从微信、浏览器或办公软件接收文件并保存到指定位置的用户。
- 项目初期主要服务开发者本人，成熟后再评估开源和通用化。

### 3.2 首台验收设备

- 设备：小米 9 透明尊享版（`cepheus`）。
- 系统：Android 11（API 30）。
- 调试方式：USB ADB。
- Root 校验：`adb shell su -c id` 必须返回 `uid=0(root)`。

### 3.3 系统范围

- 最低支持 Android 10（API 29）。
- 首轮重点验证 Android 11。
- 手机竖屏优先；横屏和平板后续适配。

## 4. 核心概念

### 4.1 位置（Location）

“位置”是首页可点击的逻辑入口，不一定等于单一目录。位置分为：

- 应用位置：微信等软件及其候选路径集合。
- 通用位置：内部存储、下载、文档、图片、视频等。
- 虚拟视图位置：应用层虚拟文件夹树及其真实文件/目录叶子引用。
- 最近位置：最近成功进入或成功保存的目录。

### 4.2 应用路径模板

应用路径模板用于描述某个软件可能使用的多个目录，包含：

- 模板 ID、软件名称、包名与图标。
- 路径显示名称和用途。
- 一个或多个绝对路径候选。
- 最低或最高适用系统版本（如需要）。
- 排序优先级。

模板只负责提供候选规则。应用启动后必须用 Root 探测实际存在性和可访问性，不得把不存在的候选路径显示成可用目录。

### 4.3 虚拟视图位置

用户可以创建不限产品层级的虚拟文件夹，并把经 Root 校验的真实文件或目录添加为叶子引用。虚拟文件夹没有 Root 路径，只用于分组；真实目录引用进入后切换到普通文件浏览，不能在虚拟树中展开真实子级。引用可设置备注、移动、移除、失效重试和重新定位；删除任何虚拟节点都只修改 iSaver 数据库，绝不删除磁盘项目。同一真实项目可位于不同虚拟文件夹，但同一父文件夹内不得重复。

## 5. 功能需求

### 5.1 Root 启动门禁

#### 功能规则

- 冷启动和进程重建后必须检查 Root 可用性。
- 首次检查可触发系统 Root 管理器的授权弹窗。
- 获得 Root 后进入主页。
- 被拒绝、超时、`su` 不存在或返回非零状态时，显示阻断页。
- 阻断页提供“重新检测”和“退出应用”，不提供功能残缺的普通模式。
- Root 会话在运行中失效时，当前操作立即失败并提示重新授权，不静默重试危险写操作。

#### 验收标准

- 有 Root 并授权时可进入主页。
- 拒绝 Root 时无法浏览应用目录，并能看到明确原因。
- 点击重新检测后可以恢复。
- Root 中途失效不闪退、不产生误导性成功提示。

### 5.2 iOS Files 风格三标签主页

底部固定三个标签：

1. **最近项目**：展示最近成功访问、保存、压缩、解压或传输的本地项目。
2. **视图**：主页面按应用位置、虚拟视图位置、通用位置的顺序展示；虚拟引用以用户备注名显示，回收站保持为通用位置最后一项。进入虚拟文件夹后切换为独立目录页，以当前备注为标题并提供返回、搜索、显示切换和当前层内容，不继续显示首页分区或面包屑。
3. **浏览**：从 Root 根目录 `/` 开始浏览完整 Android 文件系统。

“视图”是路径入口集合，不创建虚假的磁盘目录。修改备注只改变 iSaver 中的展示名称，不重命名真实目录。

#### 页面分组

首页按以下顺序展示：

1. 最近使用。
2. 应用位置。
3. 通用位置。
4. 虚拟视图位置。

“视图”页提供虚拟文件夹创建和虚拟树导航；“浏览”页从 `/` 暴露真实 Root 文件系统。真实项目通过浏览页当前路径动作或文件/目录长按动作添加到指定虚拟文件夹。

#### 交互规则

- 点击单目录位置时直接进入目录。
- 点击包含多个候选目录的应用位置时，先进入该应用的位置列表。
- 位置不可用时显示状态或隐藏不可用候选，不允许伪装成可访问。
- 返回层级为：实际目录 → 应用位置列表 → 首页 → 退出或放弃保存。
- 在分享保存流程中，只有进入实际可写目录后才启用“保存”按钮。

#### 视觉规则

- 页面背景：`#F2F2F7`。
- 卡片背景：`#FFFFFF`。
- 强调色：`#007AFF`。
- 次级文字：`#8E8E93`。
- 分割线：`#E5E5EA`。
- 横向留白：16dp。
- 卡片圆角：10dp 至 14dp。
- 列表行高度：56dp 至 68dp。
- 使用系统字体，不内置受版权限制的 Apple 字体。
- 高保真复刻参考图中的大标题、搜索框、导航栏、文件/文件夹列表、三列图标网格、底部标签栏和右上角三点菜单。
- “视图”页采用紧凑导航栏：标题与右上角三点按钮同一水平线，搜索栏紧贴导航栏下方，不再使用占据大面积高度的大标题区。
- “视图”页右上角提供“新建虚拟文件夹”；真实路径和文件的添加入口统一为“添加到虚拟视图位置”，并要求选择虚拟文件夹。
- 保留 Android 系统状态栏和系统手势区域，不伪造 iPhone 状态栏或 Home 指示条。
- 视觉验收以小米 9 ADB 截图与参考图逐项对比为准。

### 5.3 内置应用路径：微信

#### 功能规则

- 首版至少提供微信入口，包名以 `com.tencent.mm` 为主。
- 微信入口可以包含“外部共享文件”“图片/视频”“应用外部目录”“内部数据目录”等多个用途项。
- 路径必须以可维护模板定义，不把路径散落硬编码在 UI 或 ViewModel 中。
- 每次展示前异步检测候选路径是否存在、是否为目录、是否可读、是否可写。
- 路径可能因微信版本、MIUI、存储迁移、用户编号或分身环境变化；模板允许多个候选，不承诺单一路径永久有效。
- 未探测到任何微信目录时显示“未找到可用微信目录”，并引导通过 Root 浏览定位后添加到虚拟视图位置。

#### 首轮真机探测范围

- `/storage/emulated/0/Android/data/com.tencent.mm`
- `/storage/emulated/0/Android/media/com.tencent.mm`
- `/storage/emulated/0/tencent/MicroMsg`
- `/data/user/0/com.tencent.mm`
- `/data/data/com.tencent.mm`（兼容链接或旧布局）

以上是候选规则，不代表每台设备都必须存在。

### 5.4 Root 目录浏览

#### 性能要求

- 目录枚举不得为每个条目启动独立 shell/stat/base64 子进程；使用固定只读 native list-dir 单进程枚举。
- 小米 9 上 200 项普通目录冷加载首批可见 P95 目标小于 500ms，缓存命中小于 100ms。
- 返回已访问目录时先展示进程内短期快照并后台刷新；快速加载不闪烁整页转圈。
- App 启动不预读用户尚未进入的根目录；目录缓存不持久化且不作为写权限事实。

#### 展示内容

- 目录优先、文件其次，名称按不区分大小写的自然顺序排列。
- 每行显示名称、类型、大小或项目数、最近修改时间。
- 隐藏文件默认显示，因为目标用户需要访问真实应用目录；后续可增加开关。
- 无法读取的条目显示禁用态或错误状态，不能导致整个页面崩溃。

#### 交互规则

- 点击目录进入下一级。
- 点击左上返回进入上一级。
- 首版点击文件只展示基础信息，不实现任意格式预览或编辑。
- 加载过程中展示骨架或进度状态。
- 目录为空时展示空态。

#### 显示、排序与菜单

- 右上角三点菜单支持“列表”和“图标”两种单窗显示方式；图标模式手机竖屏默认三列。双窗口可在普通手机竖屏主动开启，并锁定详细列表显示。
- 支持按名称、种类、日期、大小排序，并支持升序/降序切换。
- “名称”使用当前页面的展示名称；在“视图”页即用户备注名，在真实目录中即文件系统名称。
- “种类”先按目录/文件分组，再按扩展名或条目类型稳定排序。
- 目录大小未知时不得递归扫描整个目录；使用“—”或项目数，避免排序触发高成本遍历。
- 菜单提供新建文件夹和压缩文件；不可用操作根据当前上下文禁用并解释原因。

### 5.5 自定义 Root 位置管理

#### 添加规则

- 用户输入显示名称与绝对路径。
- 路径必须以 `/` 开头，规范化后保存。
- 添加前通过 Root 检查：存在、是目录、可读；保存目标还需可写。
- 支持中文、空格和常见符号，不能依赖未经转义的 Shell 字符串拼接。
- 同一规范化路径不能重复添加。
- `/system`、`/vendor`、`/product`、`/boot` 等关键区域允许只读浏览，但添加为保存目标时必须显著警告或禁止。

#### 管理规则

- 支持修改显示名称和路径。
- 支持移除入口。
- 支持手动重新校验。
- 路径失效时保留配置并标记“不可用”。
- 移除入口不得执行 `rm`、`rmdir` 或任何磁盘删除命令。

### 5.6 新建文件夹

- 在实际可写目录中显示新建文件夹按钮。
- 弹窗默认名称为“未命名文件夹”并全选。
- 名称不能为空、不能只含空格、不能包含 `/` 或空字符。
- 通过参数化或安全转义方式执行 Root 创建命令。
- 同名目录存在时提示“文件夹已存在”。
- 创建成功后刷新并定位到新目录。

### 5.6.1 新建空文件

- 仅在普通浏览模式的实际可写目录显示“新建文件”；保存和文件操作目标选择器不显示该入口。
- 默认名称为“未命名.txt”，默认选中文件名主体；名称不做 `trim`，并执行与 Linux 目录项一致的严格 UTF-8 校验。
- 创建必须无覆盖、拒绝符号链接跟随，并绑定创建前父目录真实路径和 identity；同名项存在时提示“文件已存在”。
- 创建成功后刷新并定位新文件；结果丢失或创建后身份无法确认时提示刷新目录核对，禁止自动重试。

### 5.7 Intent 分享接收

- 注册单文件 ACTION_SEND，并注册仅匹配 content:// 的 ACTION_VIEW，MIME 类型均为 */*。
- 为两类 Intent 分别暴露“打开文件所在位置”和“保存到 iSaver”两个独立系统解析目标；两个目标必须使用不同 Activity 标签，且不得让启动器入口重复出现在分享面板中。
- 两个透明入口只负责保留来源 Intent、MIME、ClipData、读取授权并转发到主界面。“保存到 iSaver”进入现有缓存与 Root 另存状态机；“打开文件所在位置”退出另存状态并导航到可安全识别的来源父目录。
- “打开文件所在位置”首版仅识别已知微信 FileProvider authority 和 allowlist 根路径。不得把任意 `content://` 路径直接解释为 Root 路径；无法识别或路径段不安全时显示失败提示并停留在“视图”，已识别候选的存在性、目录类型和权限继续由 Root 浏览页校验并展示标准错误态。
- 不注册 SEND_MULTIPLE、file://、http(s):// 或 BROWSABLE。
- 首版接收单个文件 Uri。
- 不将 `content://` Uri 当作真实路径，必须通过 `ContentResolver` 读取。
- 无法解析名称时使用“未命名文件”并尽量保留扩展名。
- 没有读取权限时明确提示并退出本次保存流程。
- 接收后直接在现有三标签主页进入保存模式，默认展示“视图”，不展示无意义中转页，也不切换到独立 Picker。
- 微信“使用其他应用打开”和系统分享均保留“最近项目 / 视图 / 浏览”三标签；虚拟层只用于导航，用户必须经真实目录引用或 Root 浏览进入真实目录后才能选择目标。
- 保存模式下，当前页面右上角的三点菜单替换为“存储”，两者不得同时出现；只有处于已重新校验的真实可写目录且来源缓存就绪时才启用“存储”。切换到最近项目、视图等逻辑页时必须清空旧目标，防止保存到不可见目录。
- 主文件名和扩展名两个可编辑输入框放在底部标签栏正上方的内嵌保存栏中，保存栏总高度不超过 112dp；字段默认展示来源文件拆分后的原始名称，不得为空白或因系统夜间模式变成不可见白字。
- 保存成功且没有排队分享时返回来源应用；有排队分享时记录旧结果并切换到新请求，同时保留三标签主页结构。
- 主文件名必填；扩展名可空，可独立编辑为 `tar.gz` 等多段值，输入框内不包含界面单独显示的分隔点。默认来源名按最后一个非首尾点拆分，因此 `archive.tar.gz` 默认为 `archive.tar` / `gz`，`.env` 与 `name.` 的扩展名为空。
- 分享 Intent 到达后可在 Root 门禁期间并行完成元数据解析和应用私有缓存，但 Root 未授权前不得开始 Root 导航或写入；用户退出 Root 阻断页时清理本次缓存。
- Provider 元数据解析的调用方上限为 2 秒；超时显示独立的来源响应超时，可显式重试。应用会发出取消并忽略迟到结果，但不承诺终止不合作的第三方 Provider 进程。

### 5.8 文件保存

- 来源 Uri 先复制到应用私有缓存中的临时文件。
- 发布前为已验证的内部 UUID cache 生成 60 秒、一次性、256 位随机流能力；仅 UID 0（Root）或 UID 2000（Shell）可通过固定 ContentProvider 读取，首次打开即消费，过期、撤销或重放一律拒绝。
- Root 数据层只构造固定的 `content read --uri <能力 URI> | isaver-fs-helper copy-publish-stdin ...` 管道，并把 Provider 返回的文件描述符字节流交给 native helper；不把来源 Uri、用户路径或应用私有 cache 路径作为任意命令参数。
- 不得把来源明文中转到共享存储，不得为绕过 SELinux 修改 cache 权限或所有者，不得执行 `chmod`/`chown`。
- native helper 必须精确读取能力声明的字节数；提前 EOF 或多出任意字节均按来源变化失败，并精确清理本次 stage，不发布半成品。
- `/storage/emulated/0` 等 FUSE/sdcardfs 共享存储会把 Root 请求的 `0700/0600` 映射为 `0770/0660`，且可能不支持 `renameat2(RENAME_NOREPLACE)`。helper 只在确认文件系统类型、UID 0、固定映射权限、单链接和精确大小后启用共享存储发布：使用 `O_EXCL` 预留最终名称，从已验证 stage 二次复制并按身份清理，禁止静默覆盖。
- 目标同名时根据两个编辑字段生成 `主文件名 (1).扩展名` 等不冲突名称；例如主文件名 `archive`、扩展名 `tar.gz` 必须得到 `archive (1).tar.gz`，不得重新猜测成 `archive.tar (1).gz`。
- 使用目标目录中的临时文件或等价原子流程，成功后再改为最终文件名。
- 确定失败或可证明未发布时精确清理本次产生的临时文件；结果不确定时不得按路径盲删，按不确定结果策略保留来源 cache 并提示核对。
- 大文件复制在 IO 线程执行，UI 显示进度或明确的进行中状态。
- 成功后记录最近位置，并在需要时触发媒体扫描。
- 点击“存储”时重新校验来源缓存身份和目标目录的类型、可写性、符号链接及 canonical identity；列表缓存和较早的可写状态不能作为写权限事实。
- 每次 Root publish 调用都是一个不可取消的 in-flight 窗口；窗口内必须等待并核对结果，不能取消底层调用、丢弃结果、自动重放或删除不确定结果的来源缓存。明确 `ALREADY_EXISTS` 且没有待处理取消/新分享时才可在下一个窗口尝试 `(n)`；其他失败或不确定结果不得自动换名。
- 每个候选 publish 窗口必须签发全新的一次性流能力，并在 `finally` 撤销尚未消费的能力；重名后的下一候选不得复用旧 token，失败、取消和不确定结果不得自动重放已消费能力。
- 保存模式仍活跃时，可重试的确定失败保留来源缓存，但只能由用户显式重试且每次重新校验；除不确定结果外，取消、退出或不可重试的确定失败清理缓存。不确定结果只能通过“已核对并清理缓存”动作退出当前状态。
- in-flight 期间最多排队一个新分享，并立即完成其私有缓存；更新的分享替换并清理旧排队缓存。旧 Success 或不可重试的确定失败清理后切换到排队请求；可重试失败必须让用户选择“重试旧请求”或“清理旧缓存并继续排队请求”。有排队请求时旧 Success 不结束 Activity，无排队请求时才返回来源应用。
- 不确定结果在当前进程存活期间必须先展示并保留 cache，用户点击“已核对并清理缓存后继续”后才能切换或关闭。进程死亡后不按 cache 路径恢复分享，只恢复提示人工检查的脱敏 RequiresReshare 摘要；应用启动时清理超过 24 小时且没有内存 owner 的孤儿 incoming cache。

### 5.9 压缩包

当前实现状态：ZIP、TAR、TAR.GZ 和 7Z 创建，以及 ZIP/TAR/TAR.GZ/7Z/RAR 检查、安全浏览与解压已接入主界面。浏览器选择文件或目录后可在压缩对话框选择格式；归档来源先进入应用私有 incoming cache，再通过现有 Root 发布桥无覆盖写入目标目录。路径穿越、符号链接、重复条目和资源限制由 `ArchivePathPolicy`/`ArchiveLimits` 强制执行，失败或取消清理私有临时文件；归档任务进入脱敏任务中心。

- 创建支持 ZIP、TAR、TAR.GZ 和 7Z；RAR 仅浏览和解压，不创建。
- 支持浏览和解压 ZIP、TAR、TAR.GZ、7Z、RAR；RAR 只读/解压，不创建。
- 用户选择一个或多个当前目录文件或目录后创建所选格式归档；默认输出到当前目录并允许修改名称。
- 重名必须提示，禁止静默覆盖。
- 压缩、浏览和解压在 IO 线程执行，显示进度并支持取消。
- 先写入 `.isaver-<uuid>.tmp` 临时文件，校验成功后原子改名；失败或取消清理临时文件。
- 解压必须防止 Zip Slip、绝对路径、`..` 路径穿越、符号链接逃逸和解压炸弹；所有输出必须保持在用户选择的目标目录内。

### 5.10 远程服务器（本地文件管理完成后的后续阶段）

当前实现状态：远程协议模型、SFTP/FTPS/FTP 适配器、连接安全校验和私有临时下载仓库代码已存在，但产品闭环及真实服务器验收未完成。固定发布特性策略持续隐藏“连接服务器”入口，不向用户暴露远程配置、目录或传输 UI。本节只保存后续设计约束，不进入当前开发排期；只有 2.4 的本地优先发布门禁全部通过后才允许启动实现。

- 支持 SFTP、FTPS 和普通 FTP；新增连接时优先推荐 SFTP。
- 普通 FTP 连接前明确提示账号和数据可能以明文传输。
- 支持浏览远程目录、下载到本地 Root 目录、上传本地文件或文件夹、新建远程文件夹。
- 远程重命名和删除需要二次确认；这些权限不扩大本地 Root 文件的删除范围。
- 支持传输进度、取消、断线重连和失败临时文件清理。
- 不实现自动同步、后台定时同步或双向镜像。
- 连接元数据保存在 Room；密码/私钥口令使用 Android Keystore 加密，禁止明文入库、日志或 Git。

### 5.11 完整文件管理器操作（0.2.0+）

#### 文件打开

当前实现状态：普通文件单击通过私有 export cache、60 秒一次性 token、只读 URI grant 和 `ACTION_VIEW` 使用默认应用；长按“打开方式”强制显示系统 chooser。导出缓存最多读取 64 字节可信文件头修正 MIME，并保留 APK/Office 等 ZIP 容器扩展语义；纯文本和常见图片可进入绑定文件版本的内置只读预览。APK 专用安装/属性动作留在 M8 之后评审。

- 单击目录进入目录。
- 单击普通文件使用 Android 默认打开方式；没有默认应用时显示系统选择器。
- 单击支持的压缩包进入 iSaver 内部浏览器。
- 长按提供“打开方式”，允许绕过默认方式重新选择应用或内置查看器。
- Root 文件对外打开时先进入 iSaver 私有 export cache，通过一次性 `content://` URI 授权，禁止暴露真实路径。

#### 长按操作面板

- 当前实现状态：文件和目录长按均显示统一操作弹层。单/多普通文件通过一次性只读 `content://` URI 对外分享；选择中包含目录时先在应用私有缓存创建 ZIP，再签发同样的只读授权，不暴露目录 URI 或 Root 路径。文件与目录均可复制、移动、无覆盖重命名、压缩、删除和查看属性；多选支持批量复制/移动/删除/重命名。目录同名可递归合并，同名非目录保留两者；部分失败停止并报告，不自动重放。
- 单选显示：打开、打开方式、分享、移动到、复制到、重命名、压缩、删除、属性和更多。
- 多选显示：分享、移动到、复制到、压缩、删除、属性汇总和更多。
- 支持全选、反选、同类选择和批量重命名预览。
- 操作面板使用底部弹层，危险操作位于独立区域并显示风险提示。

#### 移动、复制与冲突

- “移动到”“复制到”“解压到”共用目标选择器，目标目录可新建文件夹。
- 同一文件系统优先原子无覆盖移动；跨文件系统执行复制、校验、发布、删源事务。
- 默认不覆盖；支持取消、跳过、保留两者和明确替换。
- 目标为来源自身或后代目录时拒绝操作。
- 长任务进入任务中心，取消、Root 丢失或结果不确定时不得自动重放。

#### 删除与回收站

- 共享存储默认移动到 iSaver 回收站，支持恢复和清空。
- 应用私有目录增强确认；系统关键目录默认禁止删除、移动和覆盖。
- 永久删除必须二次确认，递归删除必须经过受约束 native walker，不执行任意 `rm -rf`。

#### 其他文件管理能力

- 支持属性、权限只读展示、四种校验和、搜索、过滤、虚拟视图位置、路径历史和任务中心。
- 普通手机竖屏、横屏/平板提供双窗口；双窗口锁定详细列表显示，退出后恢复单窗显示偏好。双窗口快捷操作和单窗目标选择器共用同一安全后端。
- 文本预览、文本编辑、Hex 查看、文件对比、远程文件和 APK 深度工具按独立里程碑实施。

## 6. 安全规则

- 所有 Root 命令必须由专用数据层构造，UI 和 ViewModel 禁止拼接 Shell 命令。
- 优先使用结构化 Root 库与参数安全接口；无法避免 Shell 时必须进行严格参数引用。
- 禁止使用 `sh -c "...$userInput..."` 处理用户路径。
- 默认不提供删除和覆盖系统文件的能力。
- 日志不得记录完整敏感路径、文件内容、来源 Uri、Root 管理器信息或用户数据。
- 私有 GitHub 仓库也不得提交签名私钥、`local.properties`、Token、ADB 私钥、设备备份或真实用户文件。
- 所有写操作在执行前校验目标仍为目录且可写，防止状态变化和符号链接误导。
- 应用不得主动放宽其他应用目录权限，不执行无必要的 `chmod 777` 或递归 `chown`。

## 7. 异常流程

| 场景 | 处理方式 |
| --- | --- |
| 设备没有 Root | 阻断页提示“请以 Root 权限运行 iSaver” |
| Root 被拒绝或超时 | 显示原因，提供重新检测 |
| Root 运行中失效 | publish 窗口外终止并精确清理；窗口内先完成结果核对，再提示重新授权，不自动重放 |
| 路径不存在 | 标记位置不可用，允许编辑或移除 |
| 路径不是目录 | 拒绝添加并提示 |
| 目录不可读 | 禁用进入并显示错误 |
| 目录不可写 | 允许只读浏览，但禁用保存和新建文件夹 |
| 微信候选路径均不存在 | 提示未找到，并引导浏览定位后添加到虚拟视图位置 |
| 没有收到文件 Uri | 提示“未接收到文件”，退出保存流程 |
| Uri 无读取权限 | 提示“无法读取来源文件” |
| 文件重名 | 自动生成不冲突名称 |
| 存储空间不足 | 清理临时文件并提示空间不足 |
| 复制中断 | 仅在确定未发布时清理半成品并允许用户显式重试；结果不确定时保留来源缓存并要求核对 |
| 压缩包路径穿越 | 拒绝该条目并终止解压，不在目标目录外创建文件 |
| 压缩/解压取消 | 清理本次临时文件，不删除既有用户文件 |
| 普通 FTP | 连接前展示明文风险提示 |
| 服务器证书或主机密钥异常 | 默认阻断，要求用户明确核验，不静默信任 |
| 远程传输中断 | 保留既有文件，清理本次临时文件并允许重试 |

## 8. 非功能需求

### 8.1 性能

- Root 检查应在 2 秒内给出进度反馈。
- 位置首页在 500ms 内展示结构或骨架，路径探测异步完成。
- 普通规模目录首屏在 500ms 内给出可见反馈。
- 大目录分页或分批加载，避免一次性解析导致卡顿。
- 文件复制不阻塞主线程。

### 8.2 稳定性

- 所有 Root 调用返回结构化成功、退出码、标准输出与标准错误。
- 同进程配置变更由 ViewModel 保留当前导航与 Uri 能力；进程死亡只恢复脱敏的名称、类型、大小摘要并进入“请重新分享”，绝不恢复 Uri、缓存路径或继续保存。
- 单个异常文件名或无权限条目不能使整个目录加载失败。
- 进程重启后虚拟视图位置、最近位置和安全的浏览会话可恢复。

### 8.3 可维护性

- UI、状态管理、位置模板、Root 访问和文件复制分层实现。
- 微信等应用模板使用独立配置或 Kotlin 数据定义。
- Root 操作封装在单一模块并通过接口替换，便于单元测试。
- 每项新功能先写失败测试，再实现最小代码。
