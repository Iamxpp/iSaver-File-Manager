# iSaver 主界面内嵌保存模式设计

> 日期：2026-07-15  
> 状态：设计已确认，等待规格复核  
> 适用分支：`develop/m1-root-browsing`

## 1. 背景与目标

当前分享另存流程使用独立全屏 `ShareSavePickerScreen`，进入后隐藏“最近项目 / 视图 / 浏览”三标签，并强制打开 Root 根目录 `/`。这使用户无法通过内置位置和自定义位置选择保存目录，也偏离“在主界面基础上进入保存状态”的产品要求。

本次改为主界面内嵌保存模式：复用 iSaver 原有三标签、位置视图和目录浏览，仅在保存请求存活期间替换顶部动作并在底部标签栏上方显示紧凑文件名编辑栏。

## 2. 已确认产品决策

- 外部 `ACTION_SEND` 或 `content:// ACTION_VIEW` 请求不再进入独立 Picker 页面。
- 保存模式保留“最近项目 / 视图 / 浏览”三个标签。
- 外部文件冷启动 iSaver 时默认落在“视图”，用户可以从内置位置或自定义位置进入真实目录。
- 保存模式下，当前页面右上角“三点”替换为“存储”，不同时显示两者。
- 只有当前页面对应真实、已重新验证、可写且不是符号链接的目录时，“存储”才可用。
- “视图”根页是逻辑位置集合，不是文件系统目录，因此不能直接保存。
- 三标签栏上方显示紧凑保存栏；普通启动时不显示。
- 保存栏的主文件名和扩展名是两个独立编辑框，默认展示来源文件名拆分结果。
- 成功且没有排队请求时返回来源应用；以后进入普通 iSaver 页面时恢复三点菜单。
- 保留现有安全写入、重名、排队请求、不确定结果和缓存清理规则。

## 3. 方案比较

### 3.1 采用：主页原生保存模式

扩展 `ISaverHomeScreen`，让同一套页面根据传输状态显示普通模式或保存模式。位置、浏览器、排序、显示方式和底部导航只保留一份状态。

优点：导航一致、状态源唯一、最符合用户要求，且不会复制主页面组件。

### 3.2 不采用：主页叠加独立保存层

在现有主页之外增加覆盖层可以少改页面参数，但覆盖层需要自行同步顶部栏、目录和返回栈，容易产生两套互相冲突的目标目录状态。

### 3.3 不采用：独立 Picker 仿造三标签

在 `ShareSavePickerScreen` 中重新实现三标签会复制位置页和浏览页，后续每项 UI 或行为修改都需要维护两份实现。

## 4. 页面架构

`MainActivity` 在 Root 授权后始终渲染 `ISaverHomeScreen`，不再根据 `pickerActive` 替换整棵页面树。

`ISaverHomeScreen` 新增保存模式输入：

- 当前 `TransferUiState`。
- 文件名和扩展名修改回调。
- 存储、重试、确认不确定结果和继续排队请求回调。
- 当前目录作为保存目标的同步回调。

页面结构固定为：

```text
ISaverHomeScreen
├─ 当前标签或真实目录内容
├─ InlineSaveBar（仅保存模式）
└─ FilesBottomBar（三标签始终存在）
```

位置页和浏览页继续使用原有 ViewModel。`TransferViewModel` 只管理来源文件、名称草稿、目标验证和发布状态，不接管主页导航。

## 5. 导航与目标目录

### 5.1 进入保存模式

1. `TransferViewModel` 解析分享元数据并缓存来源文件。
2. `ISaverHomeViewModel` 选择“视图”标签并返回位置首页。
3. 不预读 `/`，也不自动选择任何目标目录。
4. 保存栏立即显示；元数据尚未完成时显示短暂准备状态，完成后填入默认名称。

### 5.2 选择位置

1. 用户在“视图”点击内置或自定义位置。
2. 主页进入现有 `HomeDestination.Browser`。
3. `BrowserViewModel` 打开对应真实目录。
4. 当前路径变化时传给 `TransferViewModel.selectTarget()`。
5. 用户返回“视图”根页或切换到不对应真实目录的标签时清除目标，存储按钮禁用。

### 5.3 保存与退出

- 点击“存储”后沿用现有发布前重新校验和不可取消 publish 窗口。
- 发布期间禁用重复点击和名称编辑，保存栏显示进行中状态。
- 成功且没有排队请求时结束当前分享 Activity 并返回来源应用。
- 有排队请求时继续显示内嵌保存模式，并按现有状态机切换请求。
- 取消或返回退出分享流程时清理允许清理的缓存；不确定结果必须先按现有规则确认。

## 6. 顶部栏设计

`FilesPageHeader` 提供互斥的右侧动作槽：

- 普通模式：圆形三点菜单。
- 保存模式：文字按钮“存储”。

所有层级继续使用 56dp 单行顶部栏，标题几何居中，搜索栏紧贴顶部栏。保存模式不改变标题和返回按钮布局。

“存储”状态：

- 可用：`#007AFF`、半粗体。
- 禁用：次级灰色，不响应点击。
- 发布中：禁用，可由保存栏状态文字说明进度。

## 7. 紧凑保存栏

保存栏位于内容区与 78dp 三标签栏之间，目标高度为 104–112dp，不覆盖系统导航区域。

从上到下：

1. 当前目录项目数，居中显示。
2. 单行名称编辑区：32×42dp 文件缩略图、主文件名输入框、独立点号、扩展名输入框。
3. 一行状态或简短输入提示；没有错误时不展示额外 MIME/大小行。

布局约束：

- 主文件名输入框使用剩余宽度。
- 扩展名输入框宽度约 72–88dp，可横向滚动显示多段扩展。
- 输入框不使用占据额外高度的浮动标签；通过语义描述区分“文件名”和“扩展名”。
- 主文件名不能为空；扩展名可空，也可为 `tar.gz`。
- 默认来源 `测试 报告.pdf` 显示为 `测试 报告` 与 `pdf`，不得出现视觉空白。

## 8. 颜色与字体稳定性

小米 9 当前处于系统夜间模式，系统 Force Dark 会把 Compose 中的深色文字转换为白色，但自绘白色背景没有同步转换，导致名称和输入内容不可见。

修复规则：

- `Theme.ISaver` 设置 `android:forceDarkAllowed="false"`。
- iSaver 首版固定使用现有浅色方案，不跟随系统夜间模式切换。
- 页面正文、分组标题、输入内容、占位文字、禁用文字和弹窗文字使用明确的 iSaver 颜色。
- 输入框通过显式 `TextFieldColors` 固定文字、光标、容器、边框和标签颜色。
- 使用 Android 系统字体，不下载或内置 Apple 字体。

## 9. 错误和边界状态

- 来源仍在解析或缓存：显示准备状态，禁止保存。
- 位置根页、最近项目空页或尚未打开浏览目录：禁止保存。
- 目录不可写、是符号链接或身份变化：保留来源缓存，提示重新选择目录。
- 名称非法：保存栏显示单行错误，保持编辑能力。
- Root 丢失：返回 Root 门禁，保留允许保留的请求状态，不自动重放写入。
- 可重试确定失败：保留来源缓存，只允许用户显式重试。
- 不确定结果：沿用确认流程，不自动清理或退出。
- 成功：记录最近项目并按是否存在排队请求决定返回来源或继续。

3. 保存模式右上角显示“存储”且不显示“三点”；普通模式相反。
